    Wind component storage measurement

    Storing u/v uses 8.90 % more Parquet bytes than speed/bearing in this 24-run sample. Here, u is eastward velocity and v is northward velocity; polar storage holds speed and meteorological bearing. Adding scalar-mean speeds increases the u/v total by another 17.90 %. The maintainer chose u/v alone. The measurement compares storage and spatial cancellation; no forecasting model was trained or scored.

    The contrasts (planned) compare u/v against polar storage, then scalar means against u/v. Planned means specified before measurement, rather than proposed future work. The sample contains the 15th and last day of every month in 2025, all at 00Z, with no unavailable dates or substitutions. Each forecast contains 85 native steps, 51 members, and 1,671 H3 cells: 7,243,785 rows per forecast and 173,850,840 rows per representation. Seasons group forecasts by initialization month; forecasts may cross season boundaries. The comparison uses the same downloaded bytes and H3 weights for all representations and the actual production write_nwp, including 13-bit significand rounding, sort order, and writer properties. Non-wind compressed-column bytes match exactly in every pair.

    Scalar-gap statistics precede writer rounding and measure spatial cancellation. Native rows receive equal weight, rather than weighting 6-hour intervals twice as much as 3-hour intervals. These descriptive sample statistics have no sampling confidence interval and should not be read as turbine-power losses or forecast-skill changes. The scalar means use grid-point magnitudes before H3 aggregation; vector magnitudes use aggregated u/v.

    Parquet totals include file metadata; Delta-log bytes are separate. MB means 10⁶ bytes.

    Reproduce the comparison

    The measurement uses frozen experimental schemas, not the current production schema. Before creating the frozen worktrees, save components.patch and scalar.patch from the current checkout's studies/wind_storage/variants/ directory outside those worktrees. Create three isolated worktrees at commit e3bcb44c, then cherry-pick 1bef88b2 and ad2ea712 into each. Keep the polar worktree unchanged; apply the saved component and scalar patches to their respective worktrees and commit each variant. Use the same uv.lock, H3 weights, and raw cache for all three. The scripts and detailed instructions are in studies/wind_storage/README.md. Generated reports and full records live under data/studies/wind_storage/; the summary provenance records hashes of the input manifest, H3 weights, measurement records, reporting script, and unmodified generated summary. The published tables copy the generated summary.

    Two independent scientific reviews found no material blockers. The reviews checked paired row inventories, non-wind byte equality, report provenance, and independent raw-grid reductions, including an extreme cancellation row. OpenAI Codex performed the reviews; human review is pending. The measurement does not establish that scalar speed is unhelpful at wind-generation sites. A matched power-forecast comparison is a separate experiment after archive migration and baseline preparation.
